Capabilities

Everything between you and six CLIs.

OcHub reads and writes each tool's live config directly, and keeps its own data in ~/.ochub/ on this machine. Nothing leaves localhost.

Relay station

Put localhost between your clients and the clouds.

A relay applies once per client. After that, switching models or upstreams happens inside OcHub and takes effect immediately — the client config is never rewritten again.

Under the hood

Native to the metal.
No webview anywhere.

OcHub is written in Rust on GPUI, the GPU-accelerated UI framework behind Zed. The control API and relay run in-process on axum; state lives in SQLite. It starts instantly and idles at almost nothing.

Interface
GPUI
Metal shaders on macOS; Wayland and X11 on Linux. The same toolkit Zed ships.
Server
axum
A loopback control API and the relay gateway, in the same process as the app.
Storage
SQLite
Providers, relays, sessions and usage — one directory, ~/.ochub/.
Updates
Signed
Packages verify against a compiled-in key; downgrades are refused. Attestation included.
No Electron No webview No browser shell GPL-3.0-or-later

First launch on macOS: the app isn't notarized yet, so approve it once under System Settings › Privacy & Security › Open Anyway. In-app updates are never quarantined — it's a one-time step.
OcHub checks for updates after launch and can install them in place from Settings → About. Signed packages only; a version that isn't newer is refused. The .deb and portable ZIP stay check-only, so they never fight apt or your file layout.
Coming from cc-switch?

A one-time, read-only import brings your providers over. OcHub owns ~/.ochub/ and never writes back to ~/.cc-switch/ — quit cc-switch before your first switch.
